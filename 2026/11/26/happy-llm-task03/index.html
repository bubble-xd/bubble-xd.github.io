Happy-LLM Task03 学习笔记：搭建一个 Transformer（2.3）

发表于2026-11-26|更新于2026-11-26|LLMHappy-LLM
|总字数:1.6k|阅读时长:6分钟|浏览量:

本篇是 Datawhale《Happy-LLM》的学习笔记，对应教材第二章：Transformer 架构的 2.3 节。接续 Task02 中的注意力层与编解码器组件，本节主要梳理输入序列如何经词嵌入和位置编码进入网络、完整 Transformer 的前向数据流与损失计算，以及按教材代码拼接时需要注意的问题。

2.3 搭建一个 Transformer

Embedding 层

文本经分词后得到的是一串离散的 token ID，需要映射成连续稠密向量才能送入神经网络计算。如果直接使用 one-hot 编码，向量维度会等于整个词表大小，不仅极度稀疏，而且任意两个词向量互相正交，无法反映语义相似度。

PyTorch 的 nn.Embedding(vocab_size, n_embd) 本质上是一个形状为 (vocab_size, n_embd) 的可学习权重矩阵（查找表）：输入形状为 (B, T) 的整型索引张量时，按索引取出对应行，输出形状变为 (B, T, n_embd)。

位置编码（PositionalEncoding）

自注意力计算对输入序列的顺序不敏感。如果不注入位置信息，把输入词序打乱，每个位置计算出的注意力只是随着位置一起重排，模型无法区分「我爱你」和「你爱我」。

不同维度对应不同频率的周期函数，使模型能够通过线性变换表达相对位置偏移，并在一定程度上外推到训练时未见过的长度。对应实现中有三个工程细节：

  • 指数换算 div_term：直接算 容易发生数值溢出，利用 写成 torch.exp(...) 计算更稳定。
  • register_buffer 注册缓冲区：位置编码矩阵不参与反向传播更新，不能用 nn.Parameter；注册为 buffer 后，调用 .to(device) 或保存/加载 state_dict 时会随模型一起迁移和存储。
  • 按当前长度切片：预计算的 pe 长度为最大序列长度 block_size，前向传播时用 :x.size(1) 截取与当前输入序列等长的部分再逐元素相加。

整体结构与前向数据流

教材在 Transformer 类中用 nn.ModuleDict 将嵌入层、位置编码、Dropout、Encoder 和 Decoder 统一放在 self.transformer 下，外接输出线性层 lm_head 将隐藏表示映射回词表空间。

对应前向逻辑与训练/推理分支如下：

阶段 输入 / 中间变量 张量形状 说明
输入检查 idx (B, T) 校验 T <= args.block_size，否则触发断言
词嵌入与位置编码 tok_emb, pos_emb, x (B, T, n_embd) 离散 ID 转向量并叠加绝对位置信息
编解码特征提取 enc_out, x (B, T, n_embd) 经 N 层注意力与 FFN 提取上下文表示
训练分支 logits, loss (B, T, vocab_size), 标量 将三维输出展平为 (B*T, vocab_size) 与 targets.view(-1) 算交叉熵
推理分支 logits, loss (B, 1, vocab_size), None 只取最后一个时间步用于预测下一个 token
  • 推理切片用 x[:, [-1], :] 而不是 x[:, -1, :]：加方括号索引可以保留时间步维度（维度仍为 3 维 (B, 1, n_embd)），避免降成 2 维 (B, n_embd)。
  • ignore_index=-1：用于跳过样本中的填充位置（padding）或不参与监督的位置，使这些位置的标签不计入交叉熵损失。
  • 权重初始化与参数统计：self.apply(self._init_weights) 递归遍历所有子模块，将 nn.Linear 与 nn.Embedding 的权重按正态分布 初始化，线性层偏置置零；get_num_params(non_embedding=False) 支持统计总参数量或剔除 wte 权重后的非嵌入参数量。

疑问与排查

对照 Task02 结尾记录的几处代码片段差异，直接按教材 2.1–2.3 的碎片拼装运行会遇到以下问题：

  1. 变量命名与维度不统一（拼接必报错）

    • 现象：MultiHeadAttention 和层定义中混用了 args.n_embd 与 args.dim；DecoderLayer.__init__ 定义的是 self.ffn_norm，forward 里误写成了 self.fnn_norm；EncoderLayer / DecoderLayer 传入 MLP 的中间维度写成了 args.dim。
    • 处理：在 ModelArgs 中统一隐藏层维度名称（统一使用 n_embd 或在配置中保留明确映射），修正 self.fnn_norm 为 self.ffn_norm，并将 MLP 隐藏层维度设为 4 * args.n_embd（或从 args.hidden_dim 读取）。

  2. Dropout 被连续调用了两次

    • 现象：PositionalEncoding.forward 末尾已经执行了 self.dropout(x)，Transformer.forward 中得到 pos_emb 后又紧接着执行 x = self.transformer.drop(pos_emb)。
    • 处理：只保留其中一处 Dropout（例如去掉 PositionalEncoding 内部的 dropout，统一由外层 self.transformer.drop 控制），避免实际丢弃率高于预期。

  3. 单序列共用 idx 同时喂给 Encoder 和 Decoder 的标签泄漏

    • 现象：教材 2.3.3 的 forward(self, idx, targets=None) 只接收一个输入 idx，并按 enc_out = self.transformer.encoder(x)、x = self.transformer.decoder(x, enc_out) 计算。
    • 原因分析：encoder 使用的是双向自注意力（is_causal=False），enc_out 的每个位置已经汇总了整条序列（包括未来位置）的信息；随后 decoder 在交叉注意力阶段（同样 is_causal=False）去查询 enc_out，导致目标序列第 个位置可以间接读取到 及之后的真实 token。
    • 适用范围：这种写法仅适合用来演示各模块的张量衔接与最小前向流程；如果做机器翻译等 Seq2Seq 任务，必须拆分为 src_idx 与 tgt_idx 两路输入分别编码和解码；如果做自回归语言模型，则应去掉 Encoder，仅保留带因果掩码的 Decoder-only 结构。
