Datawhale Agentic RL Lab Task01 学习笔记：环境配置与第一次 GRPO 训练

发表于2026-11-17|更新于2026-11-17|LLM
|总字数:2.2k|阅读时长:7分钟|浏览量:

这篇笔记记录我学习 Datawhale Agentic RL Lab 组队学习 Task01 的过程。对应的官方教程是 Getting Started：环境配置与基础概念。

这次先用 uv 配好依赖、验证 PyTRIO 和 SwanLab，再在 GSM8K 上跑了 10 步 GRPO，确认训练、指标记录和 LoRA 权重导出都能走通。正文还整理了读训练代码时用到的概念，包括重要性采样、PPO/CISPO、LoRA、OPD 和 Observation Mask。

工具与环境

  • PyTRIO：普通云服务器是租卡自己配环境，PyTRIO 则是把大模型训练能力封装成了 API。不用折腾复杂的集群分布式和 GPU 管理，直接调接口跑训练，门槛和成本低很多。
  • SwanLab：用来记录和可视化训练过程中的 loss、reward、kl 等指标。
  • uv：替代 pip/conda 的包管理工具，速度极快，依赖解析不容易打架，而且没有 Anaconda 的商业授权风险。

基础概念

  • SFT vs RL：SFT 是老师直接把标准答案给模型看，强行让模型拟合正确答案的 token 分布；RL 是给个题目让模型自己去作答（Rollout），再根据生成结果好坏给奖励（Reward），算出 Advantage 去鼓励好的、抑制差的。两者的根本区别不是知不知道答案，而是训练时是不是在无脑模仿 token。
  • Policy：对大模型来说，Policy 本质就是给定前面的上下文，预测下一个 token 的概率分布。RL 的目的就是调整参数 ，让好的 token 概率变大，差的变小。
  • Rollout：模型从 prompt 出发完整跑一遍生成的过程。在普通的问答里就是生成一段话；在 Agent 场景里，一轮 rollout 会包含多轮交互：模型思考 -> 调工具 -> 拿回环境反馈 -> 再思考 -> 输出答案，这一整条链路叫一条 trajectory。
  • On-policy vs Off-policy：On-policy 要求训练数据必须由当前最新的权重实时采样出来；如果复用旧权重采出来的数据去更新新权重，就是 Off-policy。因为新旧策略的分布有偏差，必须用重要性采样比率去拉平纠偏。
  • Reward 与 Advantage：Reward 是对回答整体打分；Advantage 是看这条回答比 Baseline 高出多少。PPO 专门训了一个 Critic 网络来预测基准线；GRPO 则简单很多，针对同一个问题采样一组回答，直接用这组回答的平均分当基准线算相对优势，不需要单独的 Critic。

重要性采样

在 RL 训练里，往往是模型先采样生成一批回答（此时记录下 Old Logprobs），然后才拿着这批数据去计算 loss 更新权重（此时算的是 Current Logprobs）。
因为权重随时在变，两者的策略并不完全一样，需要用重要性采样比率 Ratio 来衡量偏差：

比如旧模型生成某个 token 的概率是 0.2，新模型变成了 0.3： 比率等于 1.5，说明当前模型对这个 token 的偏好提升了 50%。更新时就会用这个比率去乘上 Advantage，动态调整参数更新的步长。

PPO 与 CISPO

为了防止模型一次更新太大把原本的能力学崩，两类算法对更新幅度做了不同的限制：

2. CISPO

CISPO 换了个思路：它对 Ratio 进行 clip，但通过 detach() 停止梯度把它固定为一个静态权重，再去乘 Advantage 和当前的对数概率：

两者的关键区别：

  • PPO 截断的是整个目标函数，一旦超出范围就失去梯度；
  • CISPO 只是把 Ratio 裁剪后当成固定系数，不会截断 本身的梯度，训练起来更平滑。

LoRA 与权重保存

RL 训练参数量很大，直接全量微调极耗显存，所以通常挂 LoRA：

在工程上有两种权重需要区分一下：

  • save_weights_for_sampler()：导出给推理引擎做 Rollout 生成用的权重，只包含最新的模型参数，体积小、加载快；
  • save_state()：完整的训练 Checkpoint，除了模型权重，还包含优化器状态、学习率步数等，专门用来断点续训。

在线策略蒸馏 OPD

在没有现成判题系统给 Reward 的场景下，可以用一个能力更强的 Teacher 模型来带 Student。
传统 SFT 是让 Student 死记硬背 Teacher 的答案，而 OPD 是让 Student 自己去写（根据当前策略自主探索），写完之后让 Teacher 对这篇回答逐个 token 打分批改。

1. 训练逻辑

这里利用 Reverse KL 在采样位置的概率差构造 Advantage：

  • 如果对某个 token，Teacher 觉得概率应该更高（），Advantage 就是正的，鼓励 Student；
  • 如果 Teacher 觉得这个 token 不合理，Advantage 就是负的，抑制 Student。

2. OPD 与 GRPO 对比

  • GRPO：反馈很稀疏，通常是跑完整道题给一个总的回答级分数；
  • OPD：反馈非常稠密，每一个 token 都有 Teacher 的概率对比信号，监督粒度更细。

3. OPSD 自蒸馏

如果连更大的 Teacher 模型都没有，可以用 OPSD：

  • Student 和 Teacher 是同一个模型（Teacher 冻结在第 0 步）；
  • Student 闭卷答题（只看问题 Prompt）；
  • Teacher 开卷批改（除了问题，还把参考解答给 Teacher 当上下文）。
    利用信息不对称，同一个模型就能充当自己的老师来指导训练。

Agentic RL 与 Observation Mask

普通的 RL 只是让模型输出一段纯文本，而 Agentic RL 把工具调用、执行环境的交互也放进了轨迹里。

Observation Mask 的必要性

轨迹里有两种 token：

  1. Action Tokens：模型自己生成的思考过程、工具调用命令、最终回答。
  2. Observation Tokens：外部环境返回的内容，比如搜索抓取的网页、代码执行报错、数据库返回。

核心原则：模型只需要学习“什么时候调工具、怎么调工具、怎么用工具结果”，绝不能去拟合“工具返回了什么内容”。
如果对 Observation 也计算 loss，模型就会尝试去预测搜索引擎会返回什么乱七八糟的文本，导致策略严重走偏。

把 Observation 位置的 Advantage 设为 0，反向传播时这些位置就没有梯度，真正起到了屏蔽作用。

总结

LLM 强化学习的完整流程其实很清晰：

  1. 模型拿当前 Policy 采样跑 Rollout，同时记录下 Old Logprobs；
  2. 拿到外部 Reward 或 Teacher 反馈，计算每个 token 的 Advantage；
  3. 结合 Ratio 和 PPO / CISPO 截断机制，反向传播更新模型参数；
  4. 如果是多轮 Agent，把工具返回的 Observation 彻底 mask 掉，不参与梯度更新。

实验记录

  • 环境验证：通过 uv sync 同步依赖，验证 PyTRIO 算力服务与 SwanLab 凭证连接正常，并确认支持的 Qwen 模型底座。
  • GRPO 训练日志：在 GSM8K 上完成 10 步 GRPO 快速迭代，基于重要性采样计算梯度，并在训练结束后自动导出用于 Rollout 采样的 LoRA 权重。
  • SwanLab 指标总览：实时监控 Reward 波动、退化样本比例、实际参与更新的 Token 数量以及 Loss 变化。
  • 生成长度与 Loss 曲线：rollout/avg_gen_len 显示模型的平均输出长度随探索有所增长，trainer/loss_mean 记录了策略更新的收敛趋势。
