Happy-LLM Task01 学习笔记：NLP 基础概念

发表于2026-11-18|更新于2026-11-19|LLMHappy-LLM
|总字数:2.3k|阅读时长:6分钟|浏览量:

task 01，这是我第二遍看 happy-llm。第一遍基本是划过去的，觉得这章像科普，没代码也没几个公式，看完什么也没剩下。这次我是带着一个问题读的：后面的 Transformer、BERT、GPT 到底是从哪儿长出来的。带着这个问题再看，感觉就完全不一样了，这章其实是在给整门课铺词汇表，分词、词表示、语言模型，后面所有的东西都是在这三个词上加零件。

最干的一句先记下：NLP 就是让机器理解、解释和生成语言的技术。教材还补了一句，说它横跨计算机科学、人工智能、语言学和心理学。这话听着像招生简章，但确实是这么回事，语言本身就不只是计算机问题。

发展历程

三段，教材分得很清楚。1940 到 60 年代靠规则，二战之后大家想把一种语言自动翻成另一种，1950 年图灵提了图灵测试，乔姆斯基提了生成语法，但那会儿的机器翻译说白了就是查字典加调词序，翻出来没法看。70 到 90 年代符号主义和统计方法两派打架，一边研究形式语言和生成语法，一边琢磨概率，到 80 年代算力上来、机器学习进来，统计模型开始把手写规则挤出去。2000 年代往后是深度学习，RNN、LSTM、注意力机制轮番上，2013 年 Word2Vec，2018 年 BERT，再往后 GPT-3 靠堆参数直接生成文本。

回顾整个演进脉络，本质上是把人工介入的环节一步步往后推：从最初由人手写规则，到后来的工人标注数据，再到现在人只负责设计架构并供给算力。人工先验的干预越来越少，把越来越多的特征抽取与规律总结彻底交给了模型和算力。

九个任务

教材列了九个：中文分词、子词切分、词性标注、文本分类、实体识别、关系抽取、文本摘要、机器翻译、自动问答。名字好背，做起来每个都有坑。按计划先挑三个把输入输出写清楚：

任务 输入 输出
中文分词 今天天气真好，适合出去游玩 今天 / 天气 / 真 / 好 / ， / 适合 / 出去 / 游玩 / 。
实体识别 李雷和韩梅梅是北京市海淀区的居民 李雷→人名，韩梅梅→人名，北京市海淀区→地名
机器翻译 今天天气很好。 The weather is very nice today.

中文分词那个「雍和宫的荷花开的很好」的例子我看了两遍。切错的时候挺有意思：切成「雍 / 和 / 宫的」是地名被拆散，切成「雍和 / 宫 / 的荷」是边界乱掉。人一眼就知道不对，机器不知道，因为它压根没有「词」这个概念，只有字符，所以中文得先切这一步，英文靠空格就省了。

子词切分是我这次才真正看明白的。unhappiness 切成 un + happi + ness，模型哪怕没见过这个词，也能从「否定 + 词根 + 名词后缀」拼出「不幸福的状态」。BPE、WordPiece、Unigram、SentencePiece 都是这个思路，区别只在怎么挑片段，BERT 和 GPT 全这么干，所以它们能处理没见过的词。记一句就够：模型没见过这个词，但它见过拼成这个词的零件。

剩下几个快速过一遍。词性标注就是给每个词贴标签，She/PRP is/VBZ playing/VBG，靠 HMM、CRF 或者 RNN 学；文本分类是整段映射到一个类别，比如「NBA 季后赛下周开始」归体育；关系抽取是从「比尔·盖茨是微软公司的创始人」里抽出（比尔·盖茨，创始人，微软公司）这样的三元组，是知识图谱的原料；自动问答分三种，检索式去搜，知识库问答查结构化数据，社区问答靠人堆出来的问答对。文本摘要那块有个对比值得记：抽取式是从原文里挑句子拼起来，准确但可能不连贯，生成式要重写，天问一号那段原文能压成「天问一号探测器成功实现火星着陆，代表我国在宇宙探索中取得重大进展」，后者难得多，得真理解意思才能换一种说法。

文本表示

这一节是整章的重点，四代方法其实是一条线：越来越不稀疏，越来越带上下文。

向量空间模型最朴素，词表多大向量就多长，出现的词位置填 1 其余填 0。教材那个例子是词表 16384，句子五个词，16384 维里只有 5 个 1，稀疏率 99.97%。拿这种向量算相似度，任何两个不同词的相似度都是 0，猫和狗在它眼里毫无关系，维度灾难也是这么来的。N-gram 换个思路，不看词本身，看它出现的概率，马尔可夫假设是一个词只跟前 N-1 个词有关：unigram 看自己，bigram 看前一个，trigram 看前两个，「The quick brown fox」用 trigram 就是 P(brown|The,quick) × P(fox|quick,brown)。问题是 N 一大参数就爆炸，没出现过的组合概率是 0，等于什么都没学到，而且它只往左看几个词，句子后半段和前面的关系基本抓不到。

Word2Vec 是我之前最熟的一段，这次注意到两个细节。一是 CBOW 和 Skip-gram 方向是反的，CBOW 用上下文猜中间那个词，Skip-gram 用中间的词猜上下文，小数据集 CBOW 好使，大数据集 Skip-gram 更好。二是它学的是局部上下文，所以国王和王后这种关系能出来，长距离依赖还是不行。稠密向量一般几百维，比 one-hot 省太多。ELMo 是静态到动态的那一步，同一个词在不同句子里向量不一样，一词多义终于有点办法，结构是双向 LSTM，做法是先在大量语料上训一个语言模型，再拿它给下游任务供特征。

四代放一起看就是：稀疏的表（VSM），稠密的表（Word2Vec），带上下文的表（ELMo）。再往后 BERT 把这套搬进 Transformer，就是第二章的事了。

串联思考：NLP 的三道工序

分词、词表示、语言模型看似是三个独立概念，其实是模型理解和处理语言时的三道流水线工序。

拿「雍和宫的荷花很好看」举例：

  1. 分词（切单位）：决定这句话被切成什么单位。是切成「雍和宫 / 的 / 荷花 / 很 / 好看」，还是切错成「雍 / 和 / 宫的 / 荷花」。
  2. 词表示（变数字）：决定每个单位变成什么样的向量。是 16384 维极其稀疏的 one-hot，还是 300 维稠密、带语义关联的向量。
  3. 语言模型（算概率）：决定这一串单位拼在一起的联合概率有多大，以及根据前面的词预测下一个词该出什么。

全流程就是：先切词 -> 再转成数字向量 -> 最后算概率。前一道工序如果切错了，后面的特征和概率计算全得跟着歪，这也对应了教材里为什么反复强调“分词不准确会影响整个下游流程”。

疑问与验证

  1. ELMo 到底算微调还是特征提取？

    • 思考：教材前面说“微调得到适合任务的词向量”，后面又说“提取词向量作为新特征补充到下游任务”。如果参数跟着下游任务更新才叫微调，ELMo 应该只是冻结预训练网络提取特征（Feature-based），真正的全量参数微调是 BERT 干的事。
    • 验证：这里的直觉完全正确。ELMo 确实属于典型的特征提取范式，BiLSTM 的预训练权重在下游任务中是冻结的，只把各层隐状态加权求和作为新特征喂给下游；BERT 才是主流端到端 Fine-tuning 的开端，教材在这里把两者的界限说得比较宽松。

  2. 子词切分普及后，中文分词还有必要单独做吗？

    • 思考：既然 BPE / WordPiece 已经能用子词解决未登录词（OOV），现在的 LLM 几乎全是用 Byte/Char 级别的切分，还有必要先做传统的中文分词（如 Jieba）吗？
    • 验证：在大模型端到端预训练中，确实基本不再做传统分词，而是直接用 Byte-level BPE 或 SentencePiece 统一切分；但在特定领域（如精准关键词检索、传统规则系统、知识图谱实体抽取）中，传统中文分词仍有单独存在的场景。
