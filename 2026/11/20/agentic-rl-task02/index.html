Datawhale Agentic RL Lab Task02 学习笔记：损失函数与 GRPO 实战

发表于2026-11-20|更新于2026-11-21|LLMAgentic RL
|总字数:3.8k|阅读时长:14分钟|浏览量:

这篇是 Datawhale Agentic RL Lab 组队学习的第二篇笔记。主要参考官方的 Loss Functions 和 GRPO 代码实战，最后简单记下 Vision GRPO 的思路。

这次在 GSM8K 上分别跑了 Importance Sampling、PPO 和 CISPO，也顺着同步训练脚本看了一遍：同一道题怎么采样、怎么计算组内优势，以及哪些 token 真正参与更新。

Loss Functions

  • 强化学习的本质：如果某些 token 后来被证明对结果是有用的，就让模型更容易的去生成，如果是没用的，就让模型下次少生成它们
  • advantage:衡量这一步的好坏
  • sampling_logprobs:在模型生成回答的那一刻（旧模型），它对最终选出来的这个 token 原本有多倾向（概率有多高）。
  • target_logprobs: 训练时当前模型（新模型）有多喜欢这个 token

PPO：如果 ratio 太大了，模型可能一次更新就走太远，所以 PPO 就给模型加了一个 clip 来限制范围，就是可以学习，但是不要一步冲得太远

CISPO：主要是 clip 的对象不同，ppo 是 clip objective 然后 cispo 是 clip ratio,然后把这个 ratio 当成固定系数，就是 detach()一下，然后训练模型对 logprob 做优化

GRPO

GRPO：全称 Group Relative Policy Optimization，最早是 24 年 DeepSeekMath 中提出的，论文地址：https://arxiv.org/abs/2402.03300
为什么要 GRPO 呢：PPO 好用但是太重，它是 actor-critic 方法，除了 policy model 还要训练一个 value model 来估计 baseline。
GRPO 的思路很直接：

  1. 对同一个问题，采样一组回答。
  2. 给每个回答打 reward。
  3. 不再额外训练 value model，而是用这一组回答的平均 reward 当 baseline。
  4. 比组内平均分高的回答，advantage 为正；低的为负。
  5. 用这个 advantage 去更新 policy。

这个图是 GRPO 论文中的图，其实从这里就能很清晰的看出来 PPO 存在的问题和 GRPO 的核心思想

  • PPO 的训练流程：首先将问题 q 输入 Policy Model，生成回答 o，然后通过 Reward Model 对回答进行评分，通过 Reference Model 计算 KL 散度，防止策略偏离参考模型过远。同时，还需要一个额外的 Value Model 来预测状态价值 V(s)，再结合奖励通过 GAE（广义优势估计）计算 Advantage，最终用于更新策略模型。PPO 的主要问题在于需要额外训练一个 Value Model，这不仅增加了计算和显存开销，也使训练流程更加复杂。
  • GRPO 的核心改进：直接去掉 Value Model，不再通过价值函数估计 Advantage，而是对同一个问题 q 采样生成 G 个不同回答 ，分别计算对应的奖励 ，再通过组内奖励的均值和标准差计算相对优势：

例如，同一道数学题生成 4 个回答，奖励为 [1,1,0,0]，那么奖励高于组内平均值的回答具有正 Advantage，低于平均值的回答具有负 Advantage。模型就可以根据这种相对比较，提高优质回答的生成概率，降低较差回答的生成概率。论文版 GRPO 使用重要性采样比率与裁剪，并加入参考策略的 KL 正则项。下文的 PyTRIO 示例只用奖励减去组均值计算优势，也没有显式加入参考策略 KL 项。

接下来学习 01-demo-sync.py:同步版（这里和异步版本的区别就是：异步版本只是把 batch 中的每道题的 rollout 并发的提交出去）。
这个 demo 的任务是 GSM8K 数学题。流程是：

  1. 从 GSM8K train split 取一批题。
  2. 把每道题渲染成 chat prompt。
  3. 用当前 LoRA 权重保存出一个 sampler。
  4. 对同一道题采样 group_size 个回答。
  5. 从回答里抽取最后一个 \boxed{...}。
  6. 和 GSM8K 标准答案比较，答对 reward = 1，答错 reward = 0。
  7. 在同一题的 group 内计算 advantage。
  8. 构造 PyTRIO 的 Datum。
  9. 用 importance_sampling / ppo / cispo 之一更新模型。
  10. 记录 SwanLab，最后保存 LoRA 权重。

准备 prompt 和 reward

  1. 首先 prompt要求模型把最终答案写进 \boxed{} 为了让模型更稳定地按格式回答，代码前面加了一个很小的 few-shot 示例，Qwen 模型在关闭思考模式时，标准对话模板的约定格式就是在 assistant 回答开头放一对空的 <think>\n\n</think>\n\n。few-shot 示例照着这个格式写，是为了让模型对齐格式，直接开始简短作答并输出 \boxed{...}
  1. 构造 prompt 的函数：
  • messages：用 *FEWSHOT_PREFIX 把前面的 few-shot 对话示例解包展开，再在后面拼上当前题目。
  • tokenizer.apply_chat_template(...)：按模型规定的对话模板把 messages 列表渲染成一整段带角色分隔符的字符串 prompt_text：
    • tokenize=False：先输出文本字符串，而不是直接输出 token ID。
    • add_generation_prompt=True：在末尾自动加上“轮到 assistant 回答”的提示头（如 <|im_start|>assistant\n），引导模型接着往下生成。
    • enable_thinking=False：关闭思考模式（模板会在末尾自动补上 <think>\n\n</think>\n\n），让模型直接输出简要过程和最终答案，避免思考过长浪费 token。
  • tokenizer.encode(prompt_text, add_special_tokens=False)：把文本转成模型真正接收的 token ID 列表（list[int]）。设 add_special_tokens=False 是因为上一步模板已经加好特殊控制符了，防止重复添加。
  1. 接下来就是取出答案，然后如果答案正确 reward 为 1，如果错误就是 0，这也是 RLVR，也就是 Reinforcement Learning with Verifiable Rewards，最舒服的地方：不需要先训练一个 reward model。

用当前策略采样一组回答

  1. GRPO 的采样不是每道题只生成一个答案，它必须对同一个 prompt 采样多个 completion（模型接着你的 prompt 补全出来的回答内容），因为 advantage 是组内相对值，只有一个无法比较，核心的逻辑在run_rollout_group 方法中，需要注意的是采样用的是 sampling_client,不是 training_client,在每个 step 里面，代码都会先从当前 LoRA 权重保存一个 sampler ```
  1. 这一步其实是想说明现在这个 sampler 是 old policy，后面构造 loss 的时候用到的 logprobs，必须是来自这个 old policy 的采样结果,然后 group_size 的大小其实就是同一道题采样多少次，采样完会保存 tokens(模型生成的 completion token) 、logprobs (old policy 采样时对这些 token 的 log probability)和 reward（本地打出来的分数）

第三步：计算 group-relative advantage

同一道题的所有回答都打完分以后，才计算 advantage（这里是精简实现：advantage=reward - mean_reward，GRPO 原论文中还有除以标准差），然后这里计算平均我认为主要是想体现我这个回答在这一组里面是比平均水平好还是差。

第四步：把 rollout 转成 PyTRIO Datum

Datum （英文里是 Data 的单数，意为“一条数据”）是 PyTRIO 定义的一条标准训练样本的数据结构。PyTRIO 的内置 importance_sampling 和 ppo loss 需要三类输入：

它们都要和 model_input 严格等长。在 build_grpo_datum 中大模型训练标准的 Next-Token Prediction 对齐（输入和目标错开 1 位），以及 屏蔽掉 Prompt：

举个例子：假设 prompt 有 3 个词 [P1, P2, P3]，模型生成的回答 completion 有 2 个词 [A1, A2]

位置 input_tokens (喂给模型) target_tokens (预测目标) advantages (权重) 说明
第 0 位 P1 0 (占位) 0.0 prompt 内部，不训练
第 1 位 P2 0 (占位) 0.0 prompt 内部，不训练
第 2 位 ** P3 ** (prompt 最后一个词) ** A1 ** (回答第 1 个词) ** advantage ** 开始训练！
第 3 位 ** A1 ** ** A2 ** ** advantage ** 继续训练！
  • 为什么 input_tokens 要去掉 A2（sample.tokens[:-1]）？因为 A2 已经是最后一个词了，后面没有词需要它去预测了。
  • 为什么前面要补 len(prompt) - 1 个 0.0？因为题目本身不是模型生成的，不能拿去算 RL Loss；把 advantages 填成 0.0，算 Loss 时乘上 0.0 就自动把 prompt 部分屏蔽掉了。

第五步：提交 forward/backward 和 optimizer step

收集完一个 batch 的 datums 后，训练部分其实很短：

  • BUILTIN_LOSS_FNS 是 PyTRIO 内置支持的损失函数集合。
  • 为什么 importance_sampling 和 ppo 能复用同一批 datum？因为它们需要的输入一模一样（当前 token、采样时的旧 logprob、算好的 advantage），区别只在远端算 loss 时要不要做 clip。
  • 然后做优化器更新：
  • 为什么先连续提交两个 future 最后再调 .result()？因为 PyTRIO 是异步的，把反向传播和优化器更新连续发过去排队跑，省得本地和远端来回等网络延迟。最后调 .result() 只是等待两步执行完并把指标拿回来打日志。
  • 本地代码只是把训练任务提交给 PyTRIO，真正的模型前向、反向传播、LoRA 参数更新都在远端完成。这让我可以把注意力放在 reward、advantage、loss、group size 这些算法本身，不用一直处理训练基建。

自定义 loss（以 CISPO 为例）

如果 loss 不在内置集合里（比如 CISPO），就走 else 分支用 forward_backward_custom 自定义 loss。核心逻辑其实就是：云端算当前概率，本地算 loss 梯度再传回去。

  1. 转换 Datum：
  • 为什么只留 target_tokens？因为云端重新做 forward 只需要知道 prompt 和要预测的 token，旧概率和 advantage 留在本地算 loss 就行，不需要传给远端。
  1. 用闭包传递旧数据：
  • 通过闭包把旧 logprobs、advantages 和超参数存进去，PyTRIO 调用时只需要把云端算出的当前概率 logprobs_list 传进来就能直接算。
  1. 计算 CISPO Loss：
  • 为什么加 .detach()？把 clip 后的 ratio 当作固定权重，不参与反向传播。求导时只对当前模型的 target_logprobs 求梯度（梯度大小就是 -clipped_ratio * advantage）。
  • 和 PPO 的区别：PPO 是 clip 目标，只有截断项成为较小项时（正优势且 ratio 超过上界，或负优势且 ratio 低于下界），该项的梯度才为 0；CISPO 是 clip 权重，ratio 超出后权重卡在边界，梯度依然存在，只是限制了步长不会被无限放大。
  1. 提交任务：

同样也是提交 future，最后再接 optim_step 完成更新。

loss 优化目标 稳定性手段 适合用来观察什么
importance_sampling 直接最大化 ratio * advantage 没有明显限速 reward 信号最直接怎么推动 token 概率
ppo 最大化 clipped surrogate objective clip ratio 对策略更新限速 同样 reward 下，保守更新是否更稳
cispo 最大化 detach(clipped_ratio) * logprob * advantage ratio clip 后只当固定权重 custom loss 如何控制梯度形态

运行实验

1. Importance Sampling 实验

实验配置：30 步，batch size=4，group size=8，采用 importance_sampling 损失

  1. 算力有浪费：频繁出现 datums = 0，说明模型在这几十步里做了大量的Rollout，但因为全做对了、没有产生相对比较信号，这些批次没有可用于更新的样本，实际跳过了反向传播和参数更新。
  2. GSM8K 对当前模型偏简单：对这个使用 0/1 奖励的实验，选难度适中的题更容易在同一组采样中同时得到对的和错的回答，从而形成相对优势。
  3. 后续调优思路：
    • 换更难的题目（如 MATH 数据集），降低完全做对的概率。
    • 提高 temperature 或 调大 group_size，让生成的回答更加多样化。

2. PPO 实验

(注：同一批题目下全对导致的样本退化现象仍然存在，此处重点看 PPO 的独有特征)

  1. 更新幅度收敛稳定：相较于没有限速的 Importance Sampling，PPO 在 clip 机制的约束下，后期的 Loss 震荡更收敛，稳定在 0.02 ~ 0.05 区间，但单凭 loss 曲线还不能判断策略变化的幅度。
  2. 生成长度控制健康（avg_gen_len）：平均生成长度基本维持在 250 ~ 350 tokens 之间波动，没有出现强化学习中常见的刷奖励拉长回答或推理过程骤降的退化问题。

3. CISPO 实验（自定义 Loss）

  1. Loss 多数为负：Loss 与 loss_mean 在零附近及负值区间波动，某些步接近零。这和代码中优化目标 -cispo_objective.sum() 的设定（把 clip 后的 ratio 当作常量权重去优化 target_logprobs）的目标形式有关。负值本身不表示训练异常，也不能据此判断模型表现。
  2. 策略漂移极小（Ratio 监控）：
    • cispo/ratio_mean 与 cispo/clipped_ratio_mean 高度重叠，且严格围绕 1.0 微幅波动（范围在 0.999 ~ 1.001），说明当前单步更新极其温和。
    • cispo/clip_fraction 全程为 0：因为设定的阈值范围 [0, 4.0] 较宽且更新步长稳健，没有任何 token 触发截断。此时 clip 机制起到了兜底的“安全气囊”作用。
  3. 生成长度保持一致：avg_gen_len 同样保持在 200 ~ 350 tokens，这几步的平均长度未见明显变化；生成分布和格式是否改变，还需要额外验证。
