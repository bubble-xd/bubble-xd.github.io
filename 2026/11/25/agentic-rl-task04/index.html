Datawhale Agentic RL Lab Task04 学习笔记：General OPD 原理与实战

发表于2026-11-25|更新于2026-11-25|LLMAgentic RL
|总字数:1.9k|阅读时长:7分钟|浏览量:

这篇是 Datawhale Agentic RL Lab 组队学习的第四篇笔记，对应官方实验 General OPD：在线策略蒸馏。

这次重点梳理了 On-Policy Distillation（OPD）如何通过让学生模型自主生成轨迹、再由教师模型逐 token 计算 Reverse KL 构造细粒度 Advantage，来解决传统离线蒸馏的分布偏移（Exposure Bias）问题，并在 DeepMath-103K 上跑通了最小训练闭环与 SwanLab 监控。

General OPD

On-policy Distillation（OPD，在线策略蒸馏）是知识蒸馏用在自回归生成模型上的一种做法。先理清两个概念：

  • Distillation（知识蒸馏）：将 Teacher Model 的能力迁移到 Student Model 上。
  • On-Policy：训练所使用的生成轨迹来自于 Student 自身的当前策略。

传统离线蒸馏的做法是：整理好 Question 和 Prompt，让较强的 Teacher Model 生成标准回答做成数据集，再对 Student Model 做 SFT。这种做法存在的问题是：Student 训练时看到的是 Teacher 的推理路径，但实际推理时走的是自己的路径；如果 Student 在推理中间某一步出错，就会进入训练时很少见的状态，导致错误不断累积，产生训练与推理之间的分布不一致（即 Exposure Bias：训练时即使当前步预测错了，下一步依然会输入标准答案的正确 token 继续预测；而实际推理时没有标准答案，只能在错误的 token 上继续生成）。

OPD 的解决方式是：不让 Teacher 提前写好答案，而是让 Student 先回答，再由 Teacher 对 Student 实际生成的每一个 token 进行评价。大致流程如下：从数据集中取出 Prompt，用当前 Student 采样 Completion 并保存每个 token 在旧策略下的 logprob；再由 Teacher Model 根据 Student 已经生成的轨迹计算逐 token 的 logprob，两者相减得到 reverse_kl = student_logprob - teacher_logprob；最后把 -reverse_kl 作为 Advantage，通过 importance sampling 更新 Student，刷新策略后继续下一轮采样。

这与之前学习的 GRPO 训练框架非常相似，主要区别在于训练信号的来源：GRPO 的监督信号是 Reward，OPD 的监督信号是 Teacher logprob。OPD 的优势在于监督信号更加细粒度，但 Teacher 的判断也不一定总是正确（因此 Teacher Model 需要足够强大，且能对 Student 使用的 token 序列给出可靠、对齐的 logprob），更接近 Teacher 并不必然意味着任务正确率一定会提高。
